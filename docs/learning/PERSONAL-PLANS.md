# Персональные рекомендации, планы и прогресс по номерам

Надстройка над Learning Engine: модель ученика, навыки, рекомендации и умная тренировка не дублируются. Все числа считаются из попыток ученика. AI-запросов нет — логика детерминированная.

## Диагностика: почему ученик ошибается в номере

Функция `diagnoseSkill` (`packages/shared/src/learning/diagnosis.ts`). Факты по каждой попытке готовит `apps/api/src/modules/learning/personal/data.ts` — только из данных, которые сервер может проверить сам.

| Тип | Как определяется (минимум доказательств) |
|---|---|
| `forgetting` — забывает материал | Перерыв ≥ 14 дней: до него ≥ 4 попытки и ≥ 70 % верных, после — ≥ 3 попытки и минимум на 25 п.п. хуже |
| `formula_misuse` — неправильно применяет формулу или правило | ≥ 2 неверных ответа уже после просмотра решения того же задания (`task_answer_reveals` раньше ответа или открытое объяснение в «Моих ошибках») |
| `confuses_methods` — путает похожие методы или правила | Есть ≥ 2 подтипа номера (`taskFeatures`) по ≥ 2 попытки; лучший подтип ≥ 70 %, худший ≤ 40 %, разница ≥ 35 п.п. |
| `computational` — вычислительные ошибки (только математика) | ≥ 2 неверных числовых ответа и ≥ 40 % ошибок — «почти верные»: знак, сдвиг запятой, ±10 %, ±1 |
| `condition` — не учитывает условие целиком | ≥ 2 и ≥ 40 % ошибок — частично верный ответ «запишите номера» или пустой ответ |
| `hard_tasks` — не справляется с повышенной сложностью | Базовые задания (сложность 1–2): ≥ 3 попытки и ≥ 70 %; сложные (3): ≥ 3 попытки и ≤ 40 % |
| `careless` — невнимательность | ≥ 6 попыток, ≥ 65 % верных; ≥ 2 и ≥ 50 % ошибок исправлены следующей попыткой того же задания в течение суток без открытия решения |
| `theory_gap` (русский) / `algorithm_gap` (математика) — не знает правило или алгоритм | ≥ 5 попыток, за последние 8 попыток ≤ 45 % верных, ошибки в ≥ 3 разных заданиях |
| `insufficient_data` | Меньше 4 попыток или меньше 2 ошибок. Причина не называется, предлагается диагностическая подборка |
| `unclear` | Ошибки есть, но ни одно правило не набрало доказательств. Тоже диагностическая подборка |
| `none` | ≥ 4 попыток и не больше 1 ошибки |

Если подходят несколько типов, главный — первый по таблице, остальные возвращаются в `also`. Каждый вывод сопровождается числами ученика (`evidence`).

## База советов

`adviceFor` (`packages/shared/src/learning/adviceBase.ts`). Каждый совет содержит:
- название проблемы;
- в чём ошибка и почему она возникает;
- что повторить;
- алгоритм исправления по шагам;
- практику (число и сложность заданий);
- контроль (N заданий, порог точности);
- ссылку на теорию номера в учебном центре.

Как подбирается совет:
1. **Конкретная запись для пары (номер, тип)**, если она есть. Сейчас это русский язык №13, 14, 15, 21 и математика №14 — все для типа «путает похожие».
2. **Иначе — запись предмета для этого типа ошибки** (`generic: true`). Интерфейс честно пишет, что точного совета для номера в базе пока нет.
3. **Если подходящей записи нет вовсе**, показывается совет «Нужна диагностика».

Правила ЕГЭ в базе не пересказываются и не выдумываются: совет говорит, как работать, а сами правила — на странице теории номера. `adviceCoverage()` перечисляет, что в базе есть.

## Планы на 7 и 30 дней

`buildPlan`, `planProgress`, `moveDay`, `recalculatePlan` (`packages/shared/src/learning/plans.ts`). Хранение — `learning_plans` и `learning_plan_days`.

- **Фокус плана.** Неделя — самый важный номер из рекомендаций ученика, месяц — до трёх номеров. Для каждого запоминается исходная точка: освоение, точность за 30 дней, число попыток.
- **Неделя:**

  | День | Содержание | Сложность |
  |---|---|---|
  | 1 | Теория и базовые задания | 1 |
  | 2 | Тренировка | 2 |
  | 3 | Разбор ошибок | 2 |
  | 4 | Повторение алгоритма | 2 |
  | 5 | Без подсказок | 2 |
  | 6 | Контроль | ≥ 2 |
  | 7 | Проверка прогресса | 2 |

  Сложность первого дня выше 1, если навык уже освоен лучше.
- **Месяц:** номера по очереди, один день отдыха в неделю, четвёртая неделя без подсказок, последние два дня — контроль и проверка.
- **Объём:**
  - 3–8 заданий в день: меньше для слабого навыка;
  - за весь план — не больше примерно 80 % доступных заданий навыка, чтобы задания не повторялись.
- **Выполнение.** Хранится только план. Сделанное считается из `attempts` (`planDayActuals`, `packages/db/src/learningPlans.ts`): разные задания навыка дня, решённые в дату дня (часовой пояс ученика) и после создания плана.
  - Повторный ответ на то же задание не засчитывается.
  - Открытие страницы ничего не засчитывает.
  - Теория в процент не входит.
- **Процент** = выполненные дни / дни без отдыха. Пропущенные (`skipped`) и просроченные (`missed`) дни никогда не считаются выполненными.
- **Перенос.** День и все следующие сдвигаются на день вперёд. Лимит — 3 переноса на неделю и 8 на месяц. Прошедшие, выполненные дни и дни отдыха не переносятся.
- **Пересчёт.** После выполненного дня будущие дни того же навыка подстраиваются:
  - точность ≥ 80 % — на уровень сложнее;
  - точность < 50 % — на уровень проще и на одно задание меньше.

  Контрольные дни не меняются.
- **Завершение.** Когда все дни прошли или выполнены, план закрывается один раз (условный `UPDATE`) со снимком результата.
- **«Было → стало».** Для каждого номера фокуса сравниваются освоение и точность ответов по плану с исходной точкой. Если по плану меньше 5 ответов, интерфейс пишет «мало данных», а не выдумывает рост.
- **Один активный план на предмет** обеспечивается частичным уникальным индексом. Новый план — с `replace: true`: старый отменяется.

## Прогресс по номеру

`GET /me/learning/skills/:skill/progress`, экран `/learning/progress/:skill`. Показывает:
- **освоение.** Формула v2 с априором и уверенностью; процент скрыт, пока для уровня мало данных, — один верный ответ никогда не даёт 100 %;
- решённые задания, точность, ошибки, повторные ошибки;
- точность за 7 и 30 дней против предыдущих 7 и 30 (сравнение — только при ≥ 3 попытках в обоих периодах);
- график за 30 дней: столбики — ответы в день, линия — точность за 7 дней;
- цель — следующий уровень: 55 / 75 / 90 %;
- прогресс плана и сравнение «до / после»;
- историю занятий по дням.

## Telegram-уведомления о прогрессе

`ProgressNotifier` (`apps/worker/src/reminders/progress.ts`) — в существующем цикле задач worker, через существующего бота.

| Вид | Когда |
|---|---|
| «Сегодня по плану — тренировка по …, нужно решить N заданий» | После 16:00 по местному времени, если день плана ещё не выполнен |
| «Ты закончил план. Пора пройти контрольную тренировку» | В последний день плана, если он не выполнен |
| «Ты выполнил недельную/месячную цель по … решено N, точность выросла на X %» | План завершён на ≥ 70 % |
| «Ты улучшил результат по … №N: было X %, стало Y %» | Освоение выросло на ≥ 15 п.п. по сравнению с двумя неделями ранее; достаточно данных и тогда, и сейчас; ≥ 3 попыток за неделю |

- **Кому:** Telegram привязан, бот запущен и не заблокирован.
- **Настройки** (`notification_preferences`, экран «Уведомления»):
  - «Прогресс и цели»;
  - «Напоминания по плану»;
  - частота «Только важное» — без «Сегодня по плану».

  Без сохранённых настроек всё включено, если только ученик не выключил уведомления целиком в ежедневном напоминании.
- **Отключение.** Кнопка «Не присылать о прогрессе» под каждым сообщением выключает только эти уведомления, ежедневное напоминание остаётся.
- **Время.** 10:00–21:00 в часовом поясе ученика (из настроек напоминаний, иначе Москва). Не больше двух сообщений в день, не больше 30 отправок за прогон.
- **Идемпотентность.** У каждого сообщения ключ: `today:<план>:<дата>`, `control:<план>`, `goal:<план>`, `improved:<ученик>:<навык>:<ISO-неделя>`. Строка `progress_notifications` захватывается до отправки, поэтому повтор невозможен.
- **Ошибки Telegram:**
  - не дошло (сеть) — повтор, до 5 попыток за 6 часов;
  - 429 или неверный токен — прогон останавливается;
  - «возможно показано» — без повтора;
  - блокировка бота — чат помечается.

## API

Все маршруты — в приватной области: без сессии `401`. Ученик берётся только из сессии. Чужой план отвечает `404`. Ответы идут с `no-store`.

| Метод и путь | Что делает |
|---|---|
| `GET /me/learning/personal?subject=&limit=` | Рекомендации с диагнозом и прогрессом, шапка: приоритетные темы, первичные баллы, срок |
| `GET /me/learning/skills/:skill/advice` | Совет, теория, статистика |
| `GET /me/learning/skills/:skill/progress` | Прогресс по номеру |
| `GET /me/learning/plans/current?subject=` | Активный или последний план |
| `POST /me/learning/plans` `{subjectId, kind, replace?, timezone?}` | `201`; `409` — план уже есть; `422` — не из чего строить |
| `GET /me/learning/plans/:id` | План |
| `POST /me/learning/plans/:id/days/:i/skip` | Пропустить день; `409`, если нельзя |
| `POST /me/learning/plans/:id/days/:i/move` | Перенести день; `409`, если нельзя |
| `POST /me/learning/plans/:id/cancel` | Отменить план |
| `GET` / `PUT /me/notifications/progress` | Настройки уведомлений о прогрессе |
| `POST /me/learning/sessions` | Старый маршрут, новое поле `difficulty` 1..3 (вместе с `focusSkill`): тренировка дня плана на его уровне |

## Шапка рекомендаций

- **Приоритетные темы** — рекомендации с высоким и средним приоритетом.
- **Потенциал** — сколько первичных баллов эти номера ещё могут дать: `max × (1 − освоение)`. Считается только для номеров с известными правилами баллов (математика, `examScoring.ts`). Для русского языка правил в проекте нет — показывается «—».
- **Срок** — оставшиеся дни активного плана, иначе длина недельного плана. Подпись прямо говорит, от чего он посчитан.

## Миграция 0043

Только новые таблицы: `learning_plans`, `learning_plan_days`, `notification_preferences`, `progress_notifications`. Существующие данные не меняются.

Откат вручную:

```sql
DROP TABLE progress_notifications, notification_preferences, learning_plan_days, learning_plans;
```

После этого нужно удалить запись миграции 0043 из `drizzle.__drizzle_migrations`.
