## 2. Путь данных: что работает, что нет

```
ответ → попытка → навык → статистика → рекомендация → тренировка
  ✅       ✅        ❌        ✅/⚠️           ⚠️              ⚠️
```

| Звено | Состояние | Подробно |
|---|---|---|
| Ответ → попытка | ✅ | Сервер проверяет ответ и пишет `attempts`. Повторы защищены лимитом и транзакцией. |
| Попытка → навык | **❌ не работает** | `updateSkillStatisticsForTaskAttempt` берёт навыки задания из `task_skills`, а на стенде: `skills = 0`, `task_skills = 0`, `user_skill_statistics = 0`. Связи создаёт только ручной `pnpm skills:sync`. Его нет ни в compose, ни в деплое, и даже он покрыл бы лишь часть №13–19 математики. **Ни одна попытка ни одного ученика не обновляет навык.** |
| Статистика | ✅ счётчики / ⚠️ навыки | `/progress/*` считают по `attempts` верно. Блок навыков в детализации номера (`progress/repo.ts`) читает пустую `user_skill_statistics`. |
| Рекомендация | ⚠️ полуслепая | Сигналы `skillNeed`, `recency` и `examImportance` всегда пустые (нет навыков). Работают `taskNumberNeed`, ошибки, сложность и цель. Выдаёт одно задание, а не «номер + причина + подборка». В веб-интерфейсе не используется. |
| Тренировка | ⚠️ | Подбор живой, но опирается на те же полуслепые сигналы. Пропорций «слабое / ошибки / давно / сильное» нет. После тренировки итога «что улучшилось» нет. |
| Рекомендации в UI | ❌ заглушка | На десктопе в учебном центре «Рекомендации появятся позже». |

## 3. Найденные проблемы

1. **Навыки пустые** (см. выше). Корень: связь задание → навык не входит в импорт и деплой.
2. **Разные определения «номера» и «темы»:**
   - `tasks.task_number` — номер в своей редакции. У Ященко-2027 (старая редакция, 20 заданий) №13 — финансы, а в актуальной №13 — уравнения.
   - `progress/*` и пул рекомендаций исключают этот сборник (`inAllSourcesPool`), поэтому попытки по нему пропадают из всей аналитики.
   - `tasks.topic_id` — 103 мелкие подтемы импортёров (`planimetry-circles`, `russian-nn-spelling`), разные у разных импортёров для одного номера.
   - `EXAM_TOPICS` — устойчивые темы спецификации ФИПИ, но аналитика их не использует.
3. **Формула освоения смешивает «мало данных» и «слабо»:**
   - `mastery = точность × min(1, попытки/10)`: 2 верных из 2 дают 20%. Нерешённый навык выглядит «слабым», и рекомендации тянут ученика туда, где он просто не практиковался.
   - Сложность заданий и «верно после ошибки» не учитываются.
4. **Целевой балл — уровень, а не число** (`target_score` ∈ `unknown | 60_plus | 70_plus | 80_plus | 90_plus | 95_plus | 100`; `self_reported_score` ∈ `unknown | under_40 … 90_plus`). Для приоритетов этого достаточно. Числовой прогноз ЕГЭ при таких данных давать нельзя.
5. **Рекомендация не объясняет себя по-человечески:** «Рекомендовано (score 57): …» без номера, числа ошибок и пользы.
6. **Нет оценки сложности учениками** — ни таблицы, ни API, ни UI.
7. **Диагностики как отдельной сущности нет.** Онбординг сохраняет предметы и уровни (`user_subject_profiles`), а тестовых заданий диагностики нет. Её роль играют первые попытки.

## 4. Что сохраняем

- **Таблицы:** `skills`, `task_skills`, `user_skill_statistics`, `task_statistics`, `user_error_statistics`, `user_subject_profiles`, `learning_sessions`. Дублирующих таблиц не создаём.
- **Поток попытки** в одной транзакции (`submitAttempt`).
- **Пересчёт навыка из полной истории** (никакого `+=`, который мог бы разойтись) и `rebuildUserSkillStatistics`.
- **Реестр `examSpecs.ts`** как единый источник структуры ЕГЭ.
- **Сигналы рекомендаций** (`shared/learning/recommendation.ts`), умная тренировка (`learning_sessions`), «Мои ошибки» и `/progress/*` в UI.
- **Навыки-методы** (`METHOD_TAG_SKILLS`) — как дополнительный слой для №13–19.

## 6. Риски и ограничения
- **Диагностика** не вводится как отдельный тест: её роль играют первые решения ученика, а для навыка без данных честно показывается «мало данных». Отдельный экран диагностики — следующий этап.
- **«Время занятий»** считается только по `time_spent_ms` тех попыток, где клиент его передал. Это оценка, а не учёт времени.
- **Миграции** готовятся в репозитории, на production не применяются (порядок — в `README.md`).
