# Learning Engine — алгоритмы

Всё детерминировано: никакого ИИ и случайности. Единственный «шум» — ежедневная перестановка равноценных заданий (§ 3). Он зависит от ученика, задания и даты.

## 1. Освоение навыка (`calculateSkillMastery`, `packages/shared/src/learning/mastery.ts`)
Байесовская оценка доли верных ответов по всем попыткам навыка:

```
p = (2 + Σ wᵢ·dᵢ·верноᵢ) / (4 + Σ wᵢ·dᵢ)          mastery = round(100·p)
wᵢ = 0.85^k · 0.5^(Δдней / 60)
```

- **Априор «2 из 4»** (50%):
  - одно верное решение даёт 60, одна ошибка — 40;
  - навык не прыгает до 100 и не обнуляется.
- **`k`** — сколько попыток было после этой. **`Δдней`** — давность относительно последней попытки, а не текущей даты, поэтому значение меняется только с новой попыткой и полный пересчёт даёт ту же строку.
  - Свежие ответы весят больше, поэтому «ошибся, потом решил» — прогресс.
  - Старая серия через месяц перестаёт держать уровень.
- **`dᵢ` — сложность задания:**
  - верно на сложном ×1,25, на лёгком ×0,8;
  - ошибка на лёгком ×1,25, на сложном ×0,8.
- **`confidence`** = min(1, Σwᵢ / 5)·100 — сколько данных за числом, а не уровень знаний.
- **Уровень** (`skillLevel`):

  | Условие | Уровень |
  |---|---|
  | 0 попыток | `none` («не решал») |
  | 1–2 попытки | `low_data` («мало данных», процент не показывается) |
  | ≥75 | `strong` |
  | ≥55 | `developing` |
  | иначе | `weak` |

- **Дополнительно:**
  - `trend` — последние 5 попыток против 5 предыдущих, нужно не меньше 3 в каждой половине, шаг 20 п.п.;
  - `repeatedErrorTasks` — задания с ≥2 ошибками;
  - `recoveredTasks` — задания, решённые после ошибки.

## 2. Рекомендации (`recommendSkills`, `packages/shared/src/learning/engine.ts`)
На каждый навык — одна рекомендация по самой срочной причине. Правила проверяются по порядку, срабатывает первое подходящее:

| Вид | Условие | Базовый приоритет | Заданий |
|---|---|---|---|
| `repeated_errors` | задания с ≥2 ошибками или застрял после разбора | 0,9 + 0,025·min(k, 4) | 3 |
| `weak` | уровень `weak` | 0,6 + 0,3·(1 − mastery) + 0,1·доля ошибок в последних 7 | 5 |
| `declining` | `trend = down` | 0,6 | 4 |
| `hard_for_me` | ≥2 задания решены верно, но оценены на 8+ | 0,45 | 3 |
| `low_data` | 1–2 попытки | 0,42 | 3 |
| `stale` | `developing`/`strong`, не практиковал ≥14 дней | 0,35 + 0,2·min(дни, 60)/60 | 3 |
| `unexplored` | ни одной попытки | 0,3 | 3 |

Множители:
- **Целевой балл (только математика):** цель 80+ → вторая часть ×1,15; цель 60–70 → вторая часть ×0,7, первая ×1,1.
- **Анти-повтор:** если навык решён в последние 20 часов (3+ попытки без ошибок), приоритет ×0,4. На `repeated_errors` не действует.

Ограничения:
- только выбранные предметы (без профиля — все);
- навыки без номера в актуальной редакции и сочинение не рекомендуются;
- несколько предметов делят список по квоте ⌈лимит / предметы⌉ + 1, остаток добирается по приоритету.

В тексте причины — числа самого ученика («За последние 7 попыток — 3 ошибки. Освоение 35%»). Польза — по части экзамена.

## 3. Подбор заданий (`pickTasksForSkill`, `engine/picker.ts`)
**Пул:** опубликованные задания навыка с автопроверкой (не сочинение) из «Все источники». Если их не хватает — добавляются задания отдельных источников.

**Балл задания:**

| Условие | Корзина `mistakes` | Остальные корзины |
|---|---|---|
| Открытая ошибка | +4 | +1 |
| Ошибался и ещё не решил | +2,5 | +1,2 |
| Новое | +0,5 | +2 |
| Уже решено | −2 | −2 (корзина `strong`: +0,5) |

Ещё к баллу:
- **−1,5**, если решал это задание в последние 7 дней;
- **−|эффективная сложность − целевая|**;
- **+ежедневная перестановка** 0…0,33 (sha1 от ученика, задания и даты).

**Целевая сложность** (`targetDifficultyFor`, шкала 1–3):

| Уровень / освоение | Целевая сложность |
|---|---|
| нет данных | 1,5 |
| < 45 | 1,2 |
| < 65 | 1,8 |
| < 80 | 2,3 |
| иначе | 2,8 |

Сложность растёт только при устойчивом успехе.

## 4. Умная тренировка (`planTraining`, `engine.ts`; `engine/training.ts`)
1. **Пропорции** `DEFAULT_TRAINING_MIX`: слабые 50%, ошибки 25%, давно не практиковал 15%, поддержание сильных 10%. Число заданий делится методом наибольших остатков (10 → 5/3/1/1). Можно передать свой `mix`.
2. **Кандидаты корзин:**
   - `weak` — `weak` / `declining` / `low_data` / `hard_for_me`, по возрастанию освоения, а для новичка — нерешённые номера;
   - `mistakes` — навыки с открытыми или повторными ошибками;
   - `stale` — `developing` / `strong`, не практиковал ≥7 дней;
   - `strong` — `strong`.
3. **Нехватка:** слоты пустой корзины переходят в следующую (weak → mistakes → stale → strong). Если навыков нет совсем — любые навыки предмета по возрастанию освоения. Тренировка всегда полной длины, пока есть задания.
4. **Порядок слотов** чередует корзины: weak, mistakes, stale, strong, weak…
5. **План** (слоты + освоение на старте) хранится в `learning_sessions.training_plan`. Задание слота подбирается в момент перехода к нему (§ 3) — уже с учётом ответов этой тренировки. Если для навыка слота заданий не осталось, берутся другие навыки плана.
6. **«Начать» у рекомендации** (`focusSkill`) — все слоты на один навык.
7. **Итог** — освоение до → после по каждому навыку, верно / попыток и топ-3 рекомендации по обновлённой модели.

## 5. Оценка сложности (`difficultyRating.ts`)
- **Хранение:** одна оценка 1–10 на пару (ученик, задание). Изменение обновляет строку.
- **Условие:** оценивать можно только после ответа или показа ответа.
- **Лимит:** 30 записей в минуту. Повтор того же значения записью не считается.
- **Общая сложность:**
  1. отбросить «ровных» оценщиков (10+ оценок, все одинаковые);
  2. отбросить выбросы по Тьюки [Q1 − 1,5·IQR, Q3 + 1,5·IQR];
  3. взять медиану;
  4. показывать только при ≥5 оставшихся оценках.

  Считается при чтении, поэтому всегда актуальна.
- **Две разные величины:**
  - собственная оценка ученика (`myRating`, в модели — `myAverageRating`, `hardButCorrect`);
  - общая (`community`).
- **Влияние:**
  - общая оценка сдвигает сложность для подбора: `effectiveDifficulty` = среднее авторской и медианы, переведённой в шкалу 1–3;
  - своя оценка 8+ на верно решённых — сигнал `hard_for_me` для рекомендаций и корзины `weak`.
- **Оценка никогда не меняет** верность ответа, XP и освоение.

## 6. Аналитика (`getAnalytics`, `engine/service.ts`)
- **Периоды:** сегодня (UTC), 7 и 30 дней, всё время — попытки, верные, точность, решённые задания.
- **Время** — сумма `time_spent_ms` только по попыткам, где оно было передано, каждая не больше 30 минут, плюс число таких попыток.
- **Таблица по номерам:** весь `SkillState` + `nextAction`.
- **Списки:** сильные, слабые, мало данных, ухудшаются, улучшаются.
- **Ошибки:**
  - навыки с наибольшим числом ошибок;
  - повторные ошибки;
  - «после разбора» — открытая ошибка, по которой ученик открывал объяснение и ошибся 2+ раза.

## Известные ограничения
- **Отдельной диагностики-теста нет.** Её роль играют первые ответы, а профиль (предметы, целевой балл) берётся из онбординга.
- **Прогноз балла ЕГЭ не делается:** у профиля уровни баллов, а не числа, и данных для честного прогноза мало.
- **«Застрял после разбора»** опирается на флаг `mistakes.explanation_opened` и число ошибок. Время открытия разбора не хранится.
