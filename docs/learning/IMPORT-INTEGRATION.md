# Learning Engine и импорт заданий

Новый вариант попадает в обучение сам — после импорта ничего вручную подключать не нужно.

## Как это работает
1. **Импорт.** Импортёр (`packages/db/src/import*.ts`, `russianBook/importBook.ts`) пишет задания с полями `subjectId`, `taskNumber`, `source`, `sourceYear`. Эти поля и так обязательны для каталога.
2. **Деплой.** Сервис `sync-content` запускает импортёры до старта API. При старте API (`apps/api/src/server.ts` → `syncLearningOnStartup`):
   1. `syncTaskSkills` вычисляет навыки каждого задания функцией `examSkillsForTask`:
      - редакция задания (`examEditionForTask`): Ященко-2027 — старая редакция, `sourceYear = 2026` — ЕГЭ-2026, иначе ЕГЭ-2027;
      - темы номера в этой редакции (`topicKeysForTask`).

      Затем создаёт недостающие строки `task_skills`, снимает устаревшие (если номер задания исправили) и не трогает навыки-методы.
   2. Пересчитывает `user_skill_statistics` учеников:
      - тех, чьи решённые задания получили или сменили навык;
      - тех, у кого по навыку есть попытки, но ещё нет строки статистики.
3. **Страховка.** Если задание появилось после старта API, оно связывается в транзакции первого ответа на него (`updateSkillStatisticsForTaskAttempt`). Ответ не теряется.
4. **Автоматически подхватывают новые задания** (нужен статус `published`):
   - пул рекомендаций и умных тренировок (`pickTasksForSkill` читает `task_skills`);
   - число доступных заданий навыка (`availableTasksBySkill`);
   - таблица покрытия (`learningCoverage`).

## Правила для импортёров (обязательно)
- **`subjectId` и `taskNumber`** — номер в той редакции, по которой составлен источник. Номер не переводить в другую редакцию.
- **`source` и `sourceYear`** — по ним выбирается редакция. Сборник по непринятому проекту Ященко-2027 обязан использовать `YASHCHENKO_2027_PROJECT_SOURCE`.
- **Не писать `task_skills` для тем ЕГЭ вручную** и не держать списки id заданий в коде. Связь всегда выводится из метаданных.
- **Новая редакция или формат экзамена** (новые номера, другая нумерация):
  1. сначала добавить редакцию и темы в `packages/shared/src/examSpecs.ts` (и правило в `examEditionForTask`, если нужно);
  2. потом импортировать.

  До этого такие задания попадут в «без навыка». Выдуманный навык им не создаётся, остальной импорт не ломается.
- **Сочинение** (`answerType = 'essay'`) связывается с навыком, но в тренировки и рекомендации не попадает: у него нет автопроверки.

## Как проверить после импорта
```
DATABASE_URL=… pnpm --filter @zybrilka/db learning:coverage
```
- Во всех строках «Без навыка» должен быть 0.
- Если есть строка «нет позиции в спецификации» — номер задания не найден в спецификации его редакции. Нужно исправить импортёр или `examSpecs.ts`.
- То же видно в логе API:
  - `learning: task skills synced` с полем `unmapped`;
  - `learning: task without an EGE skill (needs review)` по каждому такому заданию.

После проверки обновите `LEARNING-COVERAGE.md`, вставив вывод команды.

## Что доказывают тесты
`apps/api/src/modules/learning/engine/importIntegration.test.ts`:
1. **Новые задания попадают в существующие навыки.** Настоящий импортёр книги «Дощинский ЕГЭ-2026, 36 вариантов» (его нет в базовом тестовом контенте) + шаг старта API → все новые задания связаны со своими навыками русского языка, дубликатов навыков нет.
2. **Новые задания доступны для обучения.** Они есть в пуле подбора заданий и в числе доступных заданий навыка — без единой правки кода рекомендаций.
3. **Покрытие обновляется само** и остаётся полным.
4. **Неизвестный формат не ломает импорт.** Задание нового формата (математика №21) попадает в `unmapped` и в строку «без навыка»; навык не выдумывается.
5. **Пропущенная статистика пересчитывается.** Если у ученика есть ответы без строки статистики, шаг старта её досчитывает.

`apps/api/src/modules/learning/engine/flow.test.ts`:
- задание, добавленное после последней синхронизации, связывается при первом ответе на него.
