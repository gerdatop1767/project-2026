# Опыт (XP) и уровни

Опыт — это накопленные очки за обучение. Начисляет их только сервер, за ответ, который он сам проверил. Серия активности (`user_daily_activity`) — отдельная метрика, рейтинга пока нет.

## Где что лежит

| Что | Где |
| --- | --- |
| Правила начисления (единственное место с числами) | `apps/api/src/modules/xp/rules.ts` |
| Начисление, импорт истории, история, сводка | `apps/api/src/modules/xp/service.ts` |
| Кривая уровней (одна функция для всего) | `packages/shared/src/xp.ts` (`levelForXp`, `levelProgress`) |
| Таблицы | `xp_events`, `user_xp` (миграция `0025_xp.sql`) |
| API | `GET /api/v1/progress/xp`, `GET /api/v1/progress/xp/history?cursor=` |
| Интерфейс | чип «Уровень» в шапке → страница `/level` (`apps/web/src/screens/Level`) |

## Правила начисления

| Действие | XP |
| --- | --- |
| Первое верное решение, сложность 1 (лёгкое) | 10 |
| Первое верное решение, сложность 2 (среднее) | 15 |
| Первое верное решение, сложность 3 (сложное) | 25 |
| Первое верное решение, сложность 4 (очень сложное; пока таких заданий нет) | 35 |
| Задание с неизвестной сложностью (значение вне таблицы) | 15, в метаданных `difficultyKnown: false` |
| Повторное верное решение того же задания раньше чем через 7 дней после последнего начисления за него | 0 |
| Повторное верное решение через 7+ дней («повторение») | 30 % от полного значения, минимум 3 (25 → 8, 15 → 5, 10 → 3), не чаще раза в день |
| Неверный ответ | 0 |
| Задание из нескольких пунктов, решённое не полностью | 0 (XP только когда все пункты верны) |
| Сочинение и «Я решил» (не проверяется автоматически) | 0 |
| Открытие задания, просмотр разбора или теории | 0 |
| Завершение тренировки или варианта | 0 — опыт уже начислен за каждое верное задание внутри; отдельный бонус легко «нафармить» |

Задание из «Моих ошибок» проходит по тем же правилам. Если раньше оно не было решено верно, первое верное решение даёт полный опыт. Бонуса «за исправление» нет: иначе можно намеренно ошибиться, а потом ответить верно.

Диагностического теста в проекте пока нет: онбординг — это самооценка. Правила для него не заведены.

### Сложность

XP зависит от колонки `tasks.difficulty`. Сейчас её заполняют скрипты импорта **по части экзамена**: часть 1 → 2, часть 2 → 3 (см. `difficultyForTaskNumber` в `packages/db/src/import*.ts`). Это официальная структура КИМ, а не оценка каждого задания по отдельности. Поэтому сейчас фактически задание части 1 даёт 15 XP, части 2 — 25 XP.

Изменить сложность задания в БД — значит изменить XP **будущих** начислений за него. Уже начисленный опыт не пересчитывается, правила записаны в метаданных события (`rulesVersion`).

### Предметы

`SUBJECT_MULTIPLIER` в `rules.ts` — 1 для всех предметов: математика, русский, обществознание, английский, физика, химия, биология, информатика, история. Предмет не делает задание ценнее или дешевле, сложность уже учитывает усилие. Множитель можно поменять только с письменным обоснованием рядом.

`TASK_NUMBER_XP` задаёт точное значение для пары (предмет, номер). Сейчас таблица пуста. Новые задания и новые предметы подхватываются автоматически: правила читают только `subjectId`, `taskNumber` и `difficulty`.

## Гарантии

- **Однократность.** У каждого начисления есть ключ результата `dedupKey`: `task:<id>:first` или `task:<id>:review:<дата по Москве>`. Уникальный индекс `(user_id, dedup_key)` не даёт записать его второй раз ни при повторе запроса, ни при параллельных запросах.
- **Транзакционность.** Попытка, событие XP и сумма в `user_xp` пишутся в одной транзакции с проверкой ответа (`submitAttempt`): либо всё, либо ничего.
- **Сериализация по пользователю.** Перед начислением строка `user_xp` блокируется (`SELECT … FOR UPDATE`), поэтому два одновременных ответа одного пользователя применяются по очереди.
- **Ограничения в БД.** `CHECK (amount > 0)` и `CHECK (total_xp >= 0)`.
- **Уровень не хранится.** Он всегда равен `levelForXp(total_xp)`, поэтому шапка, страница уровня и будущий рейтинг не могут разойтись.

## Существующие пользователи

Миграция ничего не пересчитывает и не трогает существующие данные. Прошлые верные ответы превращаются в опыт **один раз, лениво**: при первом обращении пользователя к XP (шапка, страница или новый ответ) сервер берёт **первую верную попытку** по каждому заданию и начисляет за неё то же, что дал бы живой ответ, с датой той попытки. Ключи совпадают с живыми начислениями, поэтому двойного счёта нет. После этого ставится `user_xp.history_imported_at`.

Повторения из прошлого не восстанавливаются.

## Кривая уровней

Чтобы перейти с уровня k на k+1, нужно 50 XP, затем на 30, 40, 50… больше для каждого следующего уровня. Прирост ограничен +100 на уровень. Максимальный уровень — 50 (`XP_LEVEL_CURVE.maxLevel`): страница показывает отдельное состояние, опыт продолжает копиться.

| Уровень | Нужно XP всего | Заданий по 10 XP | по 15 XP | по 25 XP |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0 | 0 | 0 | 0 |
| 2 | 50 | 5 | 4 | 2 |
| 3 | 130 | 13 | 9 | 6 |
| 4 | 250 | 25 | 17 | 10 |
| 5 | 420 | 42 | 28 | 17 |
| 6 | 650 | 65 | 44 | 26 |
| 7 | 950 | 95 | 64 | 38 |
| 8 | 1 330 | 133 | 89 | 54 |
| 10 | 2 370 | 237 | 158 | 95 |
| 15 | 6 720 | 672 | 448 | 269 |
| 20 | 13 570 | 1 357 | 905 | 543 |
| 30 | 34 770 | 3 477 | 2 318 | 1 391 |

Первые три уровня берутся за одну-две тренировки. Уровни 5–10 — это десятки и сотни решённых заданий. Каждое задание даёт полный опыт только один раз, поэтому быстро «прокачаться» на одном лёгком задании нельзя. Дальнейший рост зависит от объёма разных решённых заданий по любым предметам.

Названия, картинки и награды уровней в эту систему не входят. Их можно добавить поверх `levelForXp`, не трогая начисление.

## Будущий рейтинг

Всё нужное для честного рейтинга проверяемо и уже хранится:
- `user_xp.total_xp` (с индексом);
- уровень из него;
- число решённых заданий (`attempts`, `xp_events` вида `task_first_solve`);
- активность за период (`xp_events.created_at`, `user_daily_activity`).

Публичных таблиц лидеров пока нет.

## Откат

`0025_xp.sql` только добавляет две таблицы. Для отката: убрать код начисления и выполнить `DROP TABLE xp_events, user_xp`. Данные попыток и прогресса это не затрагивает.
