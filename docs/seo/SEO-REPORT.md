Без проблем: `<html lang="ru">`, viewport, у всех `<img>` есть `alt`, нет горизонтального переполнения, нет ошибок страницы, www → без www и HTTP → HTTPS делает Caddy (301), хешированные ассеты кешируются навсегда.

## Что сделано

### 1. Единый реестр метаданных — `apps/web/src/lib/seo.ts`

- **13 индексируемых страниц** (`INDEXABLE_PAGES`): `/`, `/training`, `/subjects`, `/subjects/math`, `/subjects/russian`, `/theory`, `/materials`, `/games`, `/games/stress`, `/help`, `/faq`, `/privacy`, `/terms`. У каждой свои title (≤ 80 символов) и description; уникальность проверяет тест.
- **Правило индексации:** индексируется страница, которую гость видит с реальным содержимым.
  - `noindex, follow`: вход, профиль, статистика, достижения, ошибки, избранное, уровень, уведомления, настройки, друзья, рейтинг (имена учеников), учебный центр (на десктопе это главная), онбординг, возврат из Telegram, сессии и разборы попыток, заглушки «в разработке» (`/training/topic|random|variants`, `/mock-exams`, `/topics`), скрытый лендинг `/landing`, админка.
  - **Предметы без заданий** (английский, физика и др.) — тоже `noindex`. В базе задания есть только у математики (678 опубликованных) и русского (477). Когда появятся задания по новому предмету, его нужно добавить в `INDEXABLE_PAGES` одной записью.
- **Canonical** — абсолютный адрес без query и без слэша на конце, только у индексируемых страниц.
- **На клиенте:** `applySeo()` вызывается при каждом переходе (`lib/navigation.tsx`) и обновляет title, description, robots, canonical, `og:title/description/url` и JSON-LD.

### 2. Статический `<head>` для каждой страницы — `apps/web/seo/prerender.ts`

- Плагин сборки после `vite build` пишет `dist/<путь>.html` для каждой индексируемой страницы. Это тот же бандл, у каждой страницы свой `<head>`: title, description, robots, canonical, OG, JSON-LD. Поисковик без JS получает правильные метаданные с первого ответа.
- `dist/app.html` — оболочка для остальных маршрутов приложения, `noindex`.
- `dist/sitemap.xml` строится из того же реестра.
- В `index.html` блок `<!-- seo:start -->…<!-- seo:end -->` заменяется при сборке. Счётчик Метрики и весь остальной документ не трогаются (тест).

### 3. Сервер — `apps/web/nginx.conf`

| Запрос | Ответ |
|---|---|
| индексируемая страница | 200, её prerender-HTML |
| другой маршрут приложения (список `APP_ROUTE_PATTERN`) | 200, `app.html` (noindex) |
| любой другой путь | **404** с той же оболочкой: человек всё равно попадает в приложение |
| `/путь/` | 301 → `/путь` (query сохраняется) |
| `/index.html`, `/index` | 301 → `/` |
| `/about` | 301 → `/` |
| `/training/by-number` | 301 → `/subjects/math?mode=byNumber` |
| `/app.html`, `/app` | 404 |
| любой HTML | `Cache-Control: no-cache` (раньше так было только у `index.html`) |

- `absolute_redirect off`: редиректы относительные и не теряют https-хост Caddy.
- `application/xml` добавлен в gzip.
- Список маршрутов в nginx совпадает с `APP_ROUTE_PATTERN`. Тест сверяет оба списка и проверяет, что каждый адрес из `lib/routes.ts` считается маршрутом.
- Файл подтверждения Яндекс.Вебмастера: 200, `text/html`, без редиректа, байт в байт.

### 4. `robots.txt` — `apps/web/public/robots.txt`

- **Disallow** только для технических путей: `/admin`, `/api/`, `/login`, `/onboarding`, `/telegram-return`, `/learning/session/`, `/statistics/variants/`. Тест проверяет, что ни одна индексируемая страница не закрыта.
- **Clean-param** для Яндекса: `source&mode&n` на `/subjects/`, `n` на `/theory` и `/materials`, а также utm-метки, `yclid`, `gclid`, `ysclid`.
- **Sitemap:** `https://zybrilka.ru/sitemap.xml`.

### 5. Schema.org

- Главная — `WebSite` (с `alternateName` «Зубрилка») и `Organization` с логотипом.
- Остальные индексируемые страницы — `BreadcrumbList` по иерархии, например Главная → Предметы → Математика или Главная → Мини-игры → Ударения.
- Видимые хлебные крошки на страницы не добавлялись: это изменило бы интерфейс. Разметка описывает фактическую иерархию разделов.

### 6. Ссылки и заголовки

- Нижнее меню (мобильная версия) и боковое меню (десктоп) — теперь `<a href>`.
  - Обычный клик по-прежнему работает внутри приложения без перезагрузки; закрытые для гостя разделы так же открывают окно входа.
  - Ctrl/Cmd-клик и «копировать ссылку» работают как у обычных ссылок.
  - Вид не изменился (скриншоты 390 и 1440, светлая и тёмная темы).
- После изменений на главной 5 внутренних ссылок на мобильной вёрстке и 8 на десктопе (было 0).
- H1 на мобильной вёрстке: на главной («Готов к новой тренировке?»), в «Предметах» и на страницах предметов существующий заголовок переведён из `<p>` в `<h1>`. Текст и классы прежние. Теперь у всех индексируемых страниц ровно один H1 на обеих ширинах.

### 7. Прочее в `<head>`

- `og:site_name`, `og:locale=ru_RU`, `og:image` (логотип), `twitter:card`.
- Favicon (`/branding/v2/logo-icon-mobile.png`).

## Тесты

`apps/web/src/lib/seo.test.ts` (14 тестов):
- маршруты ↔ nginx в обе стороны;
- несуществующие пути → 404 и noindex;

## Осталось (не сделано сознательно)

1. **Размер бандла / LCP.** Один чанк на 1,25 МБ. Самый заметный выигрыш дадут:
   - ленивая загрузка экранов (`React.lazy` по маршрутам; админка уже так сделана);
   - KaTeX только на экранах с формулами.

   Это рефакторинг загрузки всех экранов, его стоит делать отдельной задачей с замером Lighthouse до и после.
2. **Видимые хлебные крошки** — решение по дизайну, разметка уже есть.
3. **Лендинг `/landing`** скрыт владельцем (G1), поэтому `noindex`. Если его вернуть, достаточно добавить запись в `INDEXABLE_PAGES`.
4. **Отдельные страницы заданий** (`/tasks/:id`) не существуют: задания открываются внутри сессии без своего адреса. Индексировать отдельные задания — это продуктовое и юридическое решение (права на тексты сборников), не техническая правка.
