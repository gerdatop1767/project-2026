### 2. Конвертация в production-формат

Все 5 вариантов (14–18) конвертированы в формат, которым уже пользуется `importRussianDoshchinsky2027Variant1.ts` (тот же интерфейс `ImportTask`/`ImportPassage`, та же схема БД, тот же паттерн upsert по `(subjectId, source, sourceVariant)`, тот же `isMainModule`-guard — файл ничего не делает, пока не запущен напрямую).

**Архитектура не менялась**: не добавлено новых полей схемы, не менялся парсер, не менялись API-контракты. Новые файлы **не вшиты** в `infra/docker-compose.yml`'s sync-content chain и **не добавлены** в `createImportedVariantsTestDb()` — это сознательное решение, чтобы не делать производственное связывание без отдельного разрешения; текущие файлы — изолированные, неактивные импортёры.

**Известное архитектурное ограничение (не исправлялось — требует вашего отдельного решения):** несколько заданий в рабочих данных (аудит №2) имели подтверждённые альтернативные ответы (`acceptedAnswers`), для которых в текущей схеме БД (`schema.tasks`) нет отдельного поля — есть только один `correctAnswer` (+ `digitSetOrderInsensitive` для цифровых перестановок). Эти альтернативы **не потеряны молча** — они задокументированы прямо в `explanationMd` каждого такого задания с явной пометкой «проверяющий должен засчитывать вручную». Если нужна настоящая поддержка альтернативных ответов — это изменение схемы, которое я не стал делать без вашего разрешения.
