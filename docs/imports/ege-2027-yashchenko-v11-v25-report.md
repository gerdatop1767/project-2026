## Как обрабатывался вариант

Устройство то же, что у Вариантов 1–10 (`packages/db/src/ege2027Yashchenko.ts`): коллекция `ege-2027-yashchenko` вне «Все источники», тег `ege-2027-variant-N`, идемпотентный импорт по ключу (источник, вариант, номер).

1. Страницы извлечены `pdfimages` без пересжатия и прочитаны по половинам. Tesseract в среде отсутствует, текстового слоя нет — условия переписаны вручную с изображений.
2. Ответы вычислены вручную и повторно скриптом (численные проверки, перебор, проверка числа решений по сетке параметра).
3. Рисунки:
   - графики, координатные плоскости — собственные SVG (`Ege2027Figures.tsx`): сетка найдена по проекциям пикселей, кривые сняты трассировкой скана, SVG наложен на скан с совмещением начала координат и масштаба; тест пересчитывает ответ из данных рисунка;
   - геометрические чертежи — точные фрагменты скана (пиксели светлее 215 → белые); координаты вырезок — в манифесте;
   - у заданий с SVG фрагмент скана хранится как эталон и не показывается.

## Проверка ответов (расширение `packages/shared`)

Обратно совместимо: ключ в научной записи (`3.105e-21`) принимает `3,105·10^-21`, `3,105*10^(-21)`, `3,105×10^−21`, `3,105e-21` и сравнивается относительно (1e−9). Для таких ключей абсолютный допуск не применяется: иначе любой ответ около нуля совпал бы с крошечной величиной.
