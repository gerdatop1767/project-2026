- идемпотентный повторный импорт по ключу (источник, вариант, номер).

## Как обрабатывался вариант

1. Страницы извлечены из PDF (`pdfimages`) без пересжатия и прочитаны по половинам страницы. Tesseract в среде отсутствует, поэтому OCR не применялся: условия переписаны вручную с изображений. Сомнительные символы сверены по увеличенным фрагментам: например, в В3 №7 показатель «5−x» отличён от «6−x» сравнением с глифами «5» и «6» на той же странице.
2. Ответы части 1 посчитаны вручную и повторно скриптом (sympy, численные проверки, перебор).
3. Часть 2 проверена отдельно для каждого задания:
   - координатами;
   - численной проверкой знака на всей области;
   - подсчётом решений по обе стороны каждой границы параметра;
   - полным перебором.
4. Рисунки:
   - **Графики, векторы, координатные плоскости** — собственные SVG (`apps/web/src/ui/TaskIllustration/Ege2027Figures.tsx`). Сетка найдена по проекциям пикселей скана, точки сняты в узлах. SVG отрисован и наложен на скан с совмещением начала координат и масштаба по каждой оси. Тест пересчитывает записанный ответ из данных рисунка.
   - **Геометрические чертежи** (треугольники, тела) — точные фрагменты скана без перерисовки, как в Вариантах 1–2: пиксели светлее 215 переведены в белый, рамки подобраны по содержимому.
   - У заданий с SVG фрагмент скана остаётся в `imageUrl` как эталон и в тренажёре не показывается.

## Проверка ответов (расширение `packages/shared`)

Обратно совместимо:
- граница или точка вида `(p±q√r)/d` и её отрицание, например `{-(18+4√69)/65}` или `(3-√5)/2`;
- ключ-отношение `a:b`: принимаются `a : b`, равная пропорция (`4:6`) и `a/b`. Порядок задаёт ключ, обратное отношение не засчитывается.
