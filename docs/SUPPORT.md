# Поддержка через Telegram-бота

## Пользователь (бот)

1. «💬 Поддержка» или `/support`: бот просит написать сообщение.
2. Следующее обычное сообщение в течение суток открывает обращение (`support_threads`), бот подтверждает приём. Принимаются текст, фото и файл (документ).
3. Пока обращение открыто, всё, что пишет пользователь, попадает в него («Добавлено к обращению»).
   - Команды и кнопки меню обращением не считаются никогда.
   - Голосовые, стикеры и видео бот вежливо отклоняет.
4. Ответы администратора приходят в этот же чат с пометкой «💬 Ответ поддержки:».
5. «Завершить обращение» закрывает его. Написать снова — опять «💬 Поддержка».

**Надёжность приёма:**
- Повторно доставленное Telegram обновление сохраняется один раз: уникальный индекс по (чат, id сообщения).
- Если база недоступна, бот просит прислать сообщение ещё раз и не делает вид, что принял.

**Уведомление владельцу:** при новом непрочитанном обращении владельцу приходит уведомление в Telegram (outbox, тип «Поддержка»; переключатель — в админке «Уведомления»). Одно на непрочитанную переписку, а не на каждое сообщение.

## Администратор (`/admin/support`)

- **Две колонки:** список обращений и переписка. На телефоне: список → переписка → «← Все обращения».
- **Список:** фильтр «Открытые / Закрытые / Все», поиск по имени, отметка непрочитанного, превью.
- **Переписка:** история со временем, фото и файлы (идут через API с сервера — токен бота наружу не попадает), статус доставки ответов, ответ, «Закрыть обращение» / «Открыть снова».
- **Обновление:** раз в 5 секунд, пока вкладка видна. Открытие помечает обращение прочитанным.
- **«Написать первым»:**
  - поиск по имени или ID, только одному человеку;
  - видно, может ли бот ему написать. Если нет — причина: Telegram не привязан, бот не запущен или заблокирован;
  - рассылки всем через этот раздел нет — для этого есть «Рассылки».

## Как устроено

- **Доступ:** только владелец (`ADMIN_OWNER_USER_IDS`), проверка на сервере (`requireAdmin`). Записи требуют заголовок `x-zybrilka-admin`, все действия пишутся в журнал аудита. Telegram id в браузер не отдаются.
- **Отправка ответов:**
  1. API только ставит ответ в очередь (`support_messages.delivery_status = pending`).
  2. Отправляет `SupportSender` в цикле worker, раз в 3 секунды.

  | Что случилось | Что делает worker |
  |---|---|
  | Telegram недоступен | повтор с растущей паузой, до 12 попыток |
  | «Возможно, показано» | `uncertain`, повтора нет |
  | Бот заблокирован | `failed: blocked`, чат помечается |
  | Неверный токен | сообщение ждёт исправления |
  | Worker упал во время отправки | при старте → `uncertain` |

- **Хранение:** всё в PostgreSQL (`support_threads`, `support_messages`, миграция 0032), переживает перезапуск. Сами файлы остаются на серверах Telegram; в базе только `file_id`.
- **Логи:** только коды ошибок и счётчики — без текста сообщений, без токена.
