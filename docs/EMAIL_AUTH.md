# Регистрация и вход по почте

Вход по почте работает рядом с VK ID и Telegram Mini App и не меняет их. Беспарольная ссылка для входа (`/auth/magic-link`) тоже осталась.

## Как это работает

| Шаг | API | Что происходит |
| --- | --- | --- |
| Регистрация | `POST /api/v1/auth/register {email, password}` | Сервер проверяет почту и пароль, хеширует пароль и сохраняет **только** хеш ссылки (24 ч) вместе с хешем пароля. Отправляет письмо «Подтвердите регистрацию». Аккаунт ещё **не создан**. |
| Подтверждение | `POST /auth/register/confirm {token}` | Ссылка `https://zybrilka.ru/login?confirm=…`. Создаются пользователь, `auth_identities(email)` и `email_credentials`, пользователь сразу входит. Ссылка одноразовая. |
| Повторное письмо | `POST /auth/register/resend {email}` или `{token}` | Новая ссылка для регистрации, которая ещё ждёт подтверждения. Работает и по истёкшей ссылке. |
| Вход | `POST /auth/login {email, password}` | Одна ошибка `invalid_credentials` для всех случаев: нет адреса, нет пароля, неверный пароль. Время ответа одинаковое: всегда считается хеш. |
| Забыли пароль | `POST /auth/password/forgot {email}` | Всегда одно письмо и одинаковый ответ. Есть аккаунт — ссылка `/login?reset=…` на 1 час, нет аккаунта — письмо «аккаунта с этим адресом нет». |
| Проверка ссылки | `POST /auth/password/reset/check {token}` | Страница сразу говорит «срок истёк», не заставляя вводить пароль. |
| Новый пароль | `POST /auth/password/reset {token, password}` | Пароль меняется, все другие сессии аккаунта завершаются, другие ссылки сброса гасятся, пользователь входит. |

Ответы с ошибками:
- `400 invalid_body`;
- `400 weak_password` + `problem` (`too_short` / `too_long` / `too_simple`);
- `400 invalid_or_used_token`;
- `410 token_expired`;
- `409 already_registered`;
- `429 too_many_requests` + `retryAfterSeconds` (и заголовок `Retry-After`);
- `502 email_send_failed`;
- `503 email_not_configured`.

Технические детали SMTP клиенту не уходят никогда.

### Безопасность

- **Пароли.** scrypt из `node:crypto` (N=2^15, r=8, p=3 — один из вариантов, рекомендованных OWASP), соль 16 байт. Формат `scrypt$15$8$3$<salt>$<hash>` позволяет позже усилить параметры. Требования: 8–128 символов, не из списка самых простых, не совпадает с адресом. Проверка на сервере (`passwordProblem` в `packages/shared/src/auth.ts`).
- **Ссылки.** 256 случайных бит, в БД только SHA-256. Ссылка одноразовая, используется атомарно (повтор и двойной клик дают «использована»). У каждой ссылки одно назначение (`purpose`): ссылку регистрации нельзя использовать как ссылку входа или сброса.
- **Перебор адресов.** Регистрация и восстановление отвечают одинаково, есть аккаунт или нет. Различается только письмо, которое получает владелец адреса.
- **Ограничения частоты.**
  - По IP: регистрация, повтор и «забыли пароль» — 10 за 10 мин; вход — 10 за 10 мин; подтверждение — 30; сброс — 20.
  - По адресу: не больше 1 письма в минуту и 5 в час. Лимит по адресу считается **до** поиска аккаунта, поэтому тоже ничего не выдаёт.
  - Неотправленное письмо не тратит лимит, а его ссылка удаляется.
- **Связывание аккаунтов.**
  - Аккаунты не объединяются автоматически никогда.
  - Регистрация на адрес, который уже есть (вход по ссылке или прошлая регистрация), не добавляет пароль. Владелец получает письмо со ссылкой «задать пароль», и только через неё, то есть доказав владение ящиком, у такого аккаунта появляется пароль.
  - Email VK- или Telegram-аккаунтов не известен и не используется.
- **Сессии.** Тот же httpOnly-cookie `session_id`, та же защита от межсайтовых POST (`rejectCrossSiteWrites`).
- **Логи.** Пишется только код ошибки SMTP (`code`, `responseCode`): ни адреса, ни пароля, ни текста ответа сервера.

## Подключение почты Яндекса

Яндекс.Почта — почтовый сервис, а не бесплатный API рассылок. Для писем от имени `zybrilka.ru` нужна **почта для домена в Яндекс 360 для бизнеса** и один ящик, например `no-reply@zybrilka.ru`.

Бесплатный тариф Яндекс 360 с корпоративной почтой для новых организаций отключён (по сообщениям прессы, весна 2023 г.). Есть платные тарифы, а по заявлению Яндекса сервис остаётся бесплатным для организаций до трёх сотрудников и некоммерческих. Действующие тарифы и суточные лимиты отправки нужно проверить на странице тарифов Яндекс 360 в момент подключения. **Бесплатность здесь не утверждается.**

Почта Яндекса подходит для транзакционных писем: подтверждение, сброс пароля. Для массовых рассылок она не предназначена и имеет суточные лимиты. При заметном росте числа регистраций стоит перейти на транзакционный сервис (например, Unisender Go, Mailganer, Postmark). Код менять не нужно, только `SMTP_*`.

### Что сделать владельцу домена

1. Подключить домен `zybrilka.ru` в Яндекс 360 для бизнеса и подтвердить его DNS-записью, которую покажет Яндекс.
2. Добавить DNS-записи:
   - **MX** `zybrilka.ru` → `mx.yandex.net`, приоритет 10. Нужна, если ящик должен и принимать почту. Для «no-reply» не обязательна, но её отсутствие ухудшает доставку.
   - **SPF** — TXT `zybrilka.ru`: `v=spf1 redirect=_spf.yandex.net`. Если SPF-запись уже есть, добавьте `include:_spf.yandex.net` в существующую, а не вторую запись.
   - **DKIM** — TXT `mail._domainkey.zybrilka.ru` с публичным ключом из админки Яндекс 360 («Почта» → «DKIM-подписи»). Ключ берётся только оттуда.
   - **DMARC** — TXT `_dmarc.zybrilka.ru`: начните с `v=DMARC1; p=none; rua=mailto:dmarc@zybrilka.ru`. Через пару недель без проблем переходите на `p=quarantine`.
   - Обновление DNS занимает от нескольких часов до суток.
3. Создать ящик `no-reply@zybrilka.ru`. Включить для него **пароли приложений**: «Безопасность» → «Пароли приложений» → тип «Почта». Создать отдельный пароль приложения для сервера.
4. Записать в `infra/.env` на сервере (не в Git):

   ```
   SMTP_HOST=smtp.yandex.ru
   SMTP_PORT=465
   SMTP_USER=no-reply@zybrilka.ru
   SMTP_PASSWORD=<пароль приложения>
   SMTP_FROM=Zybrilka <no-reply@zybrilka.ru>
   ```

   Адрес в `SMTP_FROM` должен совпадать с `SMTP_USER`: Яндекс отклоняет письма с чужим отправителем. Порт 465 — неявный TLS; 587 тоже работает, тогда STARTTLS обязателен (он включается автоматически).
5. Перезапустить контейнер API.
6. Проверить: зарегистрироваться на свой адрес и проверить письмо, в том числе папку «Спам». В заголовках письма должно быть `spf=pass`, `dkim=pass`.

Значения хоста, порта и записей сверены с публичными инструкциями. Официальную справку Яндекса из среды разработки открыть не удалось, поэтому при настройке сверьтесь с актуальным разделом «Почта для домена» в справке Яндекс 360.

Пока `SMTP_*` пусты, регистрация, повтор и восстановление честно отвечают `503 email_not_configured`. Интерфейс пишет «Отправка писем сейчас недоступна» и ничего не сохраняет. Вход по паролю для уже созданных аккаунтов от SMTP не зависит.

## База данных

Миграция `0026_email_password.sql` только **добавляет**:
- таблицу `email_credentials(user_id PK → users, password_hash, created_at, updated_at)`;
- в `magic_link_tokens` колонки `purpose` (по умолчанию `'sign_in'`, так что все старые ссылки остаются ссылками входа), `password_hash`, `user_id`, и индекс `(email, purpose)`.

Адрес хранится в одном месте — `auth_identities(provider='email')` с уникальным индексом, поэтому один адрес не может принадлежать двум аккаунтам.

Откат: удалить код и выполнить `DROP TABLE email_credentials`, а также `ALTER TABLE magic_link_tokens DROP COLUMN purpose, DROP COLUMN password_hash, DROP COLUMN user_id`. После отката пароли пропадут, аккаунты останутся.
