# «Зубрилка»: проверка перед деплоем (ЕГЭ-2027, варианты Ященко 1–25)

Проверка 30–31.10.2026, ветка `feat/math-2027-yashchenko-variants`. VPS, production-база, домен и DNS не затрагивались. Merge и PR не делались.

## Как проверялось

Локальный стенд, максимально близкий к production:
- **PostgreSQL 16** — отдельный тестовый кластер на порту 5433. База заполнена ровно так, как это делает `infra/docker-compose.yml`: цепочка `migrate` → `sync-subjects` → `sync-content`, список импортёров взят из самого compose-файла. Итог: 1176 заданий, 53 варианта.
- **API** — собранный `dist/server.js` в режиме `NODE_ENV=production`: `trustProxy`, cookie с флагом `Secure`.
- **Веб** — production-сборка `vite build` через `vite preview`, проксирует `/api` так же, как Caddy.
- **Браузер** — Chromium (Playwright), реальные клики по интерфейсу.
- **Вход:**
  - запуск Telegram Mini App воспроизводился так же, как его открывает Telegram: `#tgWebAppData=…` в адресе, `initData` подписан тестовым токеном стенда;
  - каждый «ученик» шёл со своим `X-Forwarded-For`, как за Caddy;
  - тестовые аккаунты только сгенерированные (`tg 7000000+…`, `9xxxxx`), реальных данных нет.

Скрипты проверки лежат в scratchpad сессии, в репозиторий не добавлены: `journey.cjs`, `variant-ui.cjs`, `answer-matrix.mjs`, `security.mjs`, `screens.cjs`, `perf.cjs`.

## 8. Telegram Mini App

Mini App реализован: автоматический вход по `initData`, серверная проверка подписи, связывание аккаунтов.

Проверено:
- запуск в формате, которым его открывает Telegram (`#tgWebAppData=…&tgWebAppPlatform=ios`);
- вход и создание аккаунта, данные пользователя;
- онбординг для нового и его отсутствие для старого;
- переходы между экранами, открытие заданий, кнопки;
- сохранение прогресса;
- закрытие и повторный запуск — тот же аккаунт.

Ограничения эмуляции — **не замена настоящему Telegram WebView**:
- скрипт `telegram.org/js/telegram-web-app.js` в песочнице не загружается (нет доступа в интернет);
- `Telegram.WebApp.ready/expand/openLink` не вызывались по-настоящему;
- вход через VK или Яндекс из Mini App через внешний браузер не проверялся.

**Ручной тест после деплоя** — пункт 4.2 чек-листа: iOS и Android, вход, задания, закрытие и повторное открытие.

Найденный риск:
- `POST /auth/telegram` ограничен 30 входами за 10 минут на IP;
- при ответе 429 Mini App молча остаётся гостем, прогресс не сохраняется;
- за общим NAT (школа, CGNAT мобильного оператора) так могут «не войти» десятки учеников.

Лимит — защита входа. Его не трогал, решение за владельцем. Варианты — в разделе 10.

## 13. Готовность к развёртыванию

Критически важные сценарии ученика проверены через реальный интерфейс:
- вход в Mini App, онбординг, варианты, ответы, проверка, решение, сохранение прогресса;
- статистика, ошибки, избранное, опыт, повторный вход.

Без настоящих внешних сервисов не проверены:
- вход через VK ID и Яндекс ID на сайте;
- настоящий Telegram, Safari.

Блокирующих проблем нет. Найденные P1–P2 исправлены и покрыты тестами. Миграции безопасны для существующих данных, откат кода не требует отката схемы.

## Вердикт: **READY WITH LIMITATIONS**

Можно развёртывать при условиях:
1. Перед деплоем — резервная копия базы (шаг 3.1).
2. Импорт вариантов ЕГЭ-2027 1–25 обязательно выполняется (шаг 3.4): локальный deploy-файл на VPS может его не содержать.
3. Сразу после деплоя — ручная проверка (раздел 4 чек-листа):
   - настоящий Telegram на iOS и Android;
   - Safari;
   - вход через VK ID и Яндекс ID.
4. Принять решение о лимите входа через Telegram до массового приглашения учеников из одной школы или сети.
