## 1. Что найдено

### Рассылки
Существующая система (черновик → подтверждение → снимок аудитории → очередь воркера) писала всем, кто запускал бота. Связи «рассылка → пользователь» не было, поэтому реакцию посчитать было нельзя. Новую систему не создавал: расширил существующую.

### Визиты вошедших
`users.last_seen_at` у вошедших не обновляется, отдельного журнала визитов нет. Решение: «последняя активность» — самое позднее из трёх событий:
- ответ (задание или мини-игра);
- вход (создание сессии);
- событие аналитики (только с согласием).

### Отключение уведомлений
Флага «не присылать рассылки» нет. Решение: «отключил уведомления» — это сохранённая настройка напоминаний с выключенными уведомлениями. Строка в `reminder_settings` появляется, только когда пользователь сам её сохранил.

### Мини-игры
Записывались только ответы вошедших игроков; запусков, завершений и времени не было.

### Метрика и тексты о cookie
Баннер cookie и политика утверждали «без сторонних сервисов». С Яндекс.Метрикой это стало бы неправдой.

### SEO
- Одинаковые title и description на всех страницах.
- Нет canonical, robots, sitemap.
- Неизвестные адреса отвечали 200.
- Навигация из кнопок без ссылок.
- На мобильных нет H1.

Полный список — в `docs/seo/SEO-REPORT.md`.

### Поле ответа
- Длинный ответ в однострочном поле был виден не целиком.
- Блоки ответа на экране результата вылезали за карточку и растягивали страницу.

### Решения
- Подробное решение рисовалось как «шаг 1».
- Метки шагов не выделялись.
- Формулы, записанные текстом, рвались посередине.
- На 320 и 390 px появлялась горизонтальная прокрутка страницы.

## 2. Что реализовано

### Рассылки «Возврат пользователей»
- **Готовые категории:**

  | Категория | Возраст аккаунта |
  |---|---|
  | 3 дня | 3–6 дней |
  | 7 дней | 7–19 дней |
  | 20 дней | 20–89 дней |

- **Фильтры:** даты регистрации, возраст аккаунта, последняя активность, активные дни в окне, решённые задания, предметы, мини-игры.
- **Превью и исключения:** число получателей и причины исключения считаются тем же SQL, по которому воркер делает снимок. Список без контактов; любого пользователя можно исключить вручную и вернуть.
- **Свой текст и предпросмотр** — как раньше.
- **Подтверждение:** двухшаговое, повторное нажатие отсекается условным UPDATE (409).
- **Защита от повтора этапа:** тот же этап повторно не уходит без явной отметки «повтор» (она пишется в журнал аудита).
- **Исключаются:** отключившие уведомления, пользователи без привязанного Telegram и заблокировавшие бота.
- **Кнопка со ссылкой** (необязательная): у каждого получателя своя ссылка — так считаются переходы.
- **Реакция по каждой рассылке и общая:**
  - доставлено;
  - переходы;
  - вернулись за сутки и за 7 дней;
  - занимались после рассылки, ответы;
  - решено заданий;
  - конверсия.
- **Прочтение не показывается:** Telegram его не сообщает.
- **История:** дата, автор, текст, получатели, доставлено, ошибки.

### Яндекс.Метрика
- Код счётчика вставлен дословно.
- Счётчик стартует только с согласием на cookie, один раз.
- SPA-хиты без дублей.
- Цели: `registration`, `diagnostic_start`, `task_solved`, `return_visit`.
- Файл Вебмастера байт в байт: nginx отдаёт 200 без редиректа.

### SEO
- Метаданные на каждую страницу.
- Статический `<head>` для 13 индексируемых страниц.
- sitemap.xml, robots.txt с Clean-param.
- Настоящие 404 и 301.
- Schema.org.
- Навигация из ссылок, H1 на мобильных.

### Мини-игры в админке
- **Журнал раундов:**
  - запуски (в том числе гостевые);
  - уникальные и повторные игроки;
  - завершённые раунды;
  - результат «с первого раза» и его распределение;
  - точность;
  - среднее и медианное время;
  - запуски по режимам.
- **По ответам за всю историю:**
  - активные и новые игроки;
  - точность;
  - игравшие 2+ дня;
  - возврат на следующий день и в течение 7 дней.
- **Периоды:** день / 7 / 30 / 90 дней / месяц / год / свой.
- Отчёт строится по реестру игр, так что новая игра получает его без нового кода.

### Поле ответа
Авторастущее поле: длинный ответ виден целиком. Ответы на экранах результата переносятся; длинные объединения интервалов переносятся между частями формулы.

### Решения
Единая подача:
- абзацы — отдельные блоки;
- «Шаг N» — с меткой и тонкой линией;
- «Ответ» выделен;
- display-формулы — отдельными блоками;
- текстовые формулы не рвутся;
- переполнения нет.

## 6. Новые события аналитики

Новых типов в `analytics_events` нет. Каждая новая метрика пишется туда, где её можно честно посчитать.

- **Цели Метрики** (уходят только с согласием): `registration`, `diagnostic_start` (в продукте онбординг называется диагностикой), `task_solved`, `return_visit`. Плюс SPA-хиты.

- **Переходы по кнопке рассылки** — в `broadcast_deliveries.clicked_at` / `click_count`. Это часть полученного сообщения; cookie не ставятся.

## 11. Оставшиеся проблемы

1. **Основной JS-чанк 1,25 МБ** (364 КБ gzip): влияет на LCP на мобильных. Нужна ленивая загрузка экранов — отдельной задачей с замером Lighthouse.
2. **Последняя активность вошедшего** определяется только по ответам, входам и событиям с согласием. Визит без действий не виден. Если нужен точный «последний визит», нужен журнал визитов — отдельное решение.
3. **Метрики раундов мини-игр** есть только с момента выкладки 0036. Раньше они не записывались и не восстанавливаются, и страница так и пишет.
4. **Ответы гостей в мини-играх не хранятся,** поэтому повторная отправка того же ответа гостем может посчитаться в счётчике раунда дважды. У вошедших дубли отсекаются.
5. **Кнопку рассылки нельзя прикрепить к альбому** (ограничение Telegram). Для нескольких картинок нужен режим «картинки, затем текст».
6. **Задания без отдельных адресов** не индексируются: у заданий нет своих страниц. Это продуктовое и правовое решение (тексты сборников).
7. **Решения с формулами Юникодом** (`a²`, `√`) не переводились в LaTeX: это правка содержимого. Невидимые словосоединители попадают в буфер обмена при копировании.
8. **В 1–4 px** некоторые KaTeX-формулы выступают за свой блок (глиф корня). Подсказка прокрутки при этом не показывается.
9. **GitHub API** в этой сессии недоступен (нужна авторизация коннектора), поэтому PR не обновлялся. Все коммиты запушены в ветку.

## 12. Шаги для production-деплоя

1. Сделать резервную копию базы.
2. Применить миграции: `pnpm --filter @zybrilka/db db:migrate:prod` (0036, 0037; только добавления, быстрые).
3. Пересобрать и перезапустить образы web (новый `nginx.conf`, robots, sitemap, prerender), api и worker — все три вместе: воркер использует новую схему рассылок.
4. Проверить web:
   - `curl -I https://zybrilka.ru/subjects/math` → 200;
   - `curl -I https://zybrilka.ru/nope` → 404;
   - `curl -I https://zybrilka.ru/training/` → 301;
   - `/robots.txt`, `/sitemap.xml` и `/yandex_d514299f65b97010.html` → 200, файл совпадает с исходным.
5. Яндекс.Вебмастер: подтвердить права файлом, добавить sitemap, проверить robots.txt. Google Search Console: добавить sitemap.
6. Метрика: принять cookie на сайте и убедиться, что хиты и цели приходят (счётчик 114059780, режим «отладка»).
7. Админка:
   - «Мини-игры» открывается;
   - тестовая рассылка «Отправить себе» с кнопкой доходит;
   - превью аудитории «3 дня» показывает разумное число.
8. Первые рассылки по аудитории отправлять малым этапом и смотреть «Реакцию» через сутки.
