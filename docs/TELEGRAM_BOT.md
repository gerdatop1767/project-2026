# Telegram-бот, уведомления владельцу и рассылки

Всё это работает в процессе **worker** (`apps/worker`), с тем же ботом и токеном, что и вход в Mini App. API только записывает задания в базу и в Telegram сам не пишет. Поэтому сбой Telegram не ломает регистрацию, ответ на задание или сохранение жалобы.

| Что | Где | Включается |
| --- | --- | --- |
| Ответы бота на `/start`, кнопки, инструкция iOS | worker, getUpdates | `TELEGRAM_BOT_POLLING=true` |
| Уведомления владельцу | worker, очередь `telegram_outbox` | токен + переключатели в «Уведомлениях» |
| Проверка доступности сайта | worker, `GET API_HEALTH_URL` раз в минуту | токен + `API_HEALTH_URL` |
| Рассылки | админка «Рассылки» → worker | токен + подтверждение в админке |

## Настройка окружения

В `infra/.env` (в Git не попадает):

```
TELEGRAM_BOT_TOKEN=<токен бота от BotFather>     # тот же, что для входа в Mini App
ADMIN_OWNER_USER_IDS=<users.id владельца>        # уже нужен для админки
TELEGRAM_BOT_POLLING=false                       # см. ниже, прежде чем включать
WEB_BASE_URL=https://zybrilka.ru
```

`infra/docker-compose.yml` передаёт эти переменные в контейнер `worker`. `API_HEALTH_URL` задан там же: `http://api:3000/health`. Токен не выводится в логи ни API, ни worker: клиент Telegram строит адрес запроса сам, а в ошибках остаётся только описание от Telegram.

### Перед включением `TELEGRAM_BOT_POLLING`

Читать обновления бота может **только один** процесс. Если сейчас на `@zybrilka_bot` отвечает что-то другое (сервис поддержки или конструктор ботов), то после включения ответы будет получать worker, а тот сервис — нет. Если у бота настроен webhook, worker видит ошибку 409, пишет её в лог и повторяет попытку раз в минуту. **Webhook worker не удаляет никогда**: это решение владельца (`deleteWebhook`). Уведомлениям и рассылкам polling не нужен.

## Бот

- **`/start` в первый раз:** приветственная картинка, текст и кнопки «Открыть Зубрилку» и «Скачать приложение на iOS». На https-адресе первая кнопка открывает Mini App внутри Telegram, на http — обычную ссылку.
- **Повторный `/start`:** короткое «С возвращением». В `telegram_bot_chats` остаётся одна строка на чат, растёт только `start_count`. Аккаунты бот не создаёт. Чат привязывается к аккаунту, если этот пользователь Telegram уже входил в Зубрилку.
- **Кнопка iOS и команда `/ios`:** пошаговая инструкция с картинкой: Safari → «Поделиться» → «На экран „Домой“» → «Добавить» → иконка. Отдельного приложения в App Store нет, так прямо и написано.
- **Прочее:** неизвестная команда — подсказка со списком команд; обычный текст — вежливый ответ, что бот пока не отвечает на сообщения. Групповые чаты игнорируются.

Картинки лежат в `apps/worker/assets/`:
- `welcome.png` (1280×720) — приветствие;
- `ios-install.png` (1080×1600) — инструкция. Это схема с явной пометкой «Это схема, а не скриншот».

Исходники в `apps/worker/assets/source/` (HTML, фирменный маскот и шрифты сайта). Пересборка: `render.mjs`, комментарий в файле. Каждая картинка загружается в Telegram один раз, дальше отправляется по `file_id`; он хранится в `app_settings`.

## Уведомления владельцу

Раздел админки **«Уведомления»** — три независимых переключателя. Они хранятся в `app_settings`, `admin.notifications`, переживают перезапуск, а каждое изменение пишется в журнал действий.

1. **Новые регистрации** — время, способ входа, кампания (если была), ID. Не больше одного уведомления на аккаунт: ключ `registration:<id>`. Повторный вход и повторный `/start` ничего не присылают.
2. **Сбои сайта:**
   - ответы API 5xx (кроме `/health`), сгруппированные по «метод + маршрут + статус + тип ошибки»;
   - по одной группе — не чаще раза в 15 минут; следующее уведомление сообщает, сколько повторов было приглушено;
   - текст ошибки не отправляется, только её тип: в тексте могут оказаться данные пользователя;
   - отдельно worker раз в минуту проверяет `/health`: после двух неудач подряд — «Сайт недоступен», пока сбой длится — напоминание раз в час, затем «Сайт снова работает». Ошибки 4xx поломкой не считаются.
3. **Жалобы на задания** — RPT-номер, предмет, задание, категория, текст (до 300 символов), время и кнопка «Открыть жалобу».

**Кто получает.** Только владельцы из `ADMIN_OWNER_USER_IDS`, у которых к аккаунту привязан Telegram (вход в Mini App или «Профиль → Способы входа») и которые нажали в боте `/start`. Username не используется. Если чего-то не хватает, раздел «Уведомления» показывает, какой шаг сделать, а кнопка «Отправить тестовое уведомление» проверяет доставку.

**Если переключатель выключен:** регистрации, жалобы и логирование ошибок работают как раньше, просто без сообщения в Telegram.

## Рассылки

Раздел админки **«Рассылки»**. Порядок работы:

1. **«Новая рассылка»** создаёт черновик. Задайте текст: переносы строк и HTML-форматирование Telegram (`<b>`, `<i>`, `<u>`, `<s>`, `<a href>`, `<code>`, `<pre>`, `<blockquote>`, `<tg-spoiler>`).
2. **Изображения** — до 10 файлов JPEG/PNG по 5 МБ, уходят в порядке добавления. Выберите режим: текст подписью к изображению (до 1024 символов) или изображения, а затем текст отдельным сообщением.
3. **«Сохранить черновик»**, предпросмотр справа. **«Отправить себе»** — сообщение придёт только владельцам.
4. **«Перейти к отправке…»** фиксирует текст и показывает число получателей и предупреждение, что сообщение получат все доступные подписчики бота.
5. **«Подтвердить отправку»**, затем ещё раз в диалоге. Только после этого worker начинает отправку. «Вернуться к редактированию» и «Отменить» доступны до подтверждения.
6. **Во время отправки** — прогресс и кнопка «Остановить». Новые сообщения перестают уходить сразу.

**Гарантии:**
- Получатели — только чаты, где нажали `/start` и не заблокировали бота. Список фиксируется одним `INSERT … SELECT` в `broadcast_deliveries` и в память не загружается.
- Одному чату рассылка приходит не больше одного раза (первичный ключ «рассылка + чат»).
- Запустить одну рассылку дважды нельзя: подтверждение — один условный UPDATE `awaiting_confirmation → sending`, второй клик получает 409.
- Скорость около 20 сообщений в секунду. На HTTP 429 worker ждёт `retry_after` и повторяет тот же чат, такой случай не считается ошибкой.
- Если пользователь заблокировал бота, доставка получает статус `blocked`, а чат исключается из следующих рассылок.
- Перезапуск worker посреди отправки: «зависшие» доставки помечаются `interrupted` и **не отправляются повторно** — лучше одна недоставка, чем дубль. Остальные продолжают уходить.
- В истории — статус, автор, даты, текст, вложения (с `file_id`), число получателей, доставленных, ошибок и заблокировавших. О получателях хранится только `chat_id` и короткий код ошибки.

Подтверждение рассылки кнопкой прямо в Telegram (п. 4.4 задания) не сделано: управление только из админки.

## Жалобы и «Скопировать для Claude»

- **В задании** (мобильная шапка ⚠ и десктоп): «Сообщить об ошибке» — 8 категорий; одного выбора достаточно. Для «Другая причина» нужен текст. Ограничение — 1000 символов, двойное нажатие отправляет один раз.
- **Что хранится:** ID задания, экран, путь и вариант, откуда отправлено, и снимок задания `task_snapshots`. Снимок общий для всех жалоб на одну версию задания, поэтому жалоба остаётся понятной после правки задания.
- **Админка «Жалобы»:**
  - поиск по `RPT-12`, ID жалобы или задания;
  - фильтры по предмету, категории и статусу, сортировка по дате;
  - карточка: полное условие (как было при жалобе и как сейчас), ответ, решение, источник, вариант, контекст;
  - статусы, внутренний комментарий, отметка «дубликат»;
  - кнопки «Скопировать для Claude» (полный структурированный отчёт), «Краткая версия» и «ID жалобы». Если браузер не даёт доступ к буферу обмена, текст появляется в поле для ручного копирования.
- **В отчёте для Claude** — только реальные данные жалобы. Чего нет, то записано как `not available`.

## Миграции

Применяются обычным `migrate` при развёртывании, по порядку. Все только добавляют таблицы и колонки, существующие данные не меняются:

1. `0027_complaint_reports` — колонки жалоб (`report_number`, `context`, `snapshot_id`, `duplicate_of_id`, `handled_by_user_id`) и таблица `task_snapshots`;
2. `0028_telegram_bot_chats` — чаты бота;
3. `0029_telegram_outbox` — очередь уведомлений;
4. `0030_broadcasts` — рассылки, вложения и доставки.
