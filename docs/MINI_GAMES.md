# Мини-игры

## Для пользователя

- **Вход:** «Задания» → карточка «Мини-игры» (`/games`) → карточка игры → «Играть».
- **Первая игра — «Ударения»** (`/games/stress`), задание 4 ЕГЭ по русскому:
  - Слово показывается без ударения, «ё» пишется как «е» (иначе ударение видно сразу). Нужно нажать на ударную гласную. Нажимаются только гласные, кнопки не меньше 44 px.
  - Проверяет сервер: в вопросе правильного ответа нет. После ответа видно правильную форму («тОрты»), неверный выбор зачёркнут.
  - **Ошибка:** «Повторить слово» сразу, и слово ещё раз вернётся через 3 вопроса (один раз за раунд). Итог раунда считает только первый ответ на каждое слово.
  - **Режимы:**
    - «Все слова» — сначала невыученные, выученные только для добивки раунда;
    - «Мои ошибки» — последний ответ был неверным;
    - «Сложные слова» — где больше всего ошибок.

    Раунд — 20 слов, порядок перемешивается на сервере (`crypto.randomInt`).
  - **Прогресс** (для вошедших): выучено N из M (выучено = 2 верных ответа подряд), верно / неверно / точность, сложные слова, ответы по дням за 2 недели. «Продолжить тренировку» продолжает с сохранённого прогресса.
  - **Гость** играет без сохранения. «Мои ошибки» и «Сложные слова» просят войти.

## Словарь ударений — источник и статус проверки

Данные: `packages/db/src/stressDictionary/data.ts`, у каждого набора указан источник (`stress_sources`).

| Что | Статус |
|---|---|
| Состав слов | Орфоэпический словник ФИПИ прошлых лет (широко воспроизводимая редакция). **С PDF ФИПИ построчно не сверен:** fipi.ru и doc.fipi.ru недоступны из среды разработки (сетевая политика). Каждое слово — `fipi_unverified`. |
| «Орфоэпический список – 2026» | Существует: на него ссылается навигатор подготовки ФИПИ-2026 для задания 4. Файл получить не удалось, его данные **не импортированы**. Это **не полный официальный перечень на 2026 год**, и интерфейс так и говорит. |
| Слова, которых, по сообщениям, нет в списке 2026 | нарОст, пОручни, жилОсь, зАтемно — по вторичному источнику (rustutors.ru), помечены `reported_removed`. В игре остаются (норма верная), при ответе показывается пометка. |
| Ударение | По разметке ФИПИ. Разработчик сверял его с нормами нормативного орфоэпического словаря (Резниченко), но сам словарь в среде недоступен, поэтому это **не** документированное подтверждение — нужна проверка редактором. Слова с допустимыми вариантами получают `disputed` и в игре не показываются никогда. |
| Вспомогательная сверка | Задание 4 восемнадцати вариантов Дощинского-2027 из проекта (`stressDictionary/audit.ts`). 73 из 90 вариантов ответа согласуются со словарём, 9 расходятся, 8 слов в словаре нет. Сам источник противоречит себе и местами ошибается, словарь по нему не меняется. Отчёт: `docs/imports/stress-dictionary-audit-2026.md`. |
| Формы | Формы с разным ударением — отдельные записи («зАнял / занялА / зАняли», «кремЕнь / кремнЯ»), не объединяются. |

**Как довести словарь до подтверждённого:**
1. Открыть сеть к fipi.ru (настройки окружения → Network access → Allowed domains) или положить PDF «Орфоэпический список – 2026» в репозиторий.
2. Построчно сверить с `data.ts`: добавить недостающие слова, пометить отсутствующие, совпавшим поставить `fipi_verified`.
3. Прогнать `pnpm --filter @zybrilka/db test` — тесты словаря.
4. Запустить импорт.

## Импорт и проверка данных

- **Валидация** (`validateStressEntries`, `packages/shared/src/miniGames.ts`):
  - ровно одна заглавная буква, и это гласная;
  - не меньше двух гласных;
  - «ё» всегда ударная;
  - известная часть речи;
  - нет дублей: одна и та же ударная форма дважды запрещена, разные формы — нет.
- **Импорт:** `pnpm --filter @zybrilka/db db:import:stress` (в production — `node node_modules/@zybrilka/db/dist/stressDictionary/import.js`).
  - Идемпотентен: upsert по ключу формы, id слов (и прогресс игроков) сохраняются.
  - Слово, убранное из данных, деактивируется, а не удаляется.
  - Если хоть одна строка невалидна, импорт ничего не пишет.
- **Подключение к деплою:** в `infra/docker-compose.yml` (файл из репозитория) импорт — последний шаг сервиса `sync-content`, через `&&` после импортов вариантов.
  - Выполняется после `migrate` и `sync-subjects` и до запуска `api` / `worker`: у них `depends_on: sync-content: service_completed_successfully`.
  - Ошибка импорта даёт ненулевой код, `sync-content` падает, `api` / `worker` не стартуют. Проверено тестом `packages/db/src/deploySyncContent.test.ts`.
  - Как подключить на VPS (там свой `docker-compose.deploy.yml`) — в `docs/DEPLOYMENT.md`, раздел «Словарь ударений на VPS».

**Проверено на тестовой PostgreSQL 16** тем же бандлом, что кладётся в образ (`pnpm --filter @zybrilka/api deploy --prod`):
- чистая база → миграции → импорт: 222 формы, 5 источников;
- повторный импорт: id слов, прогресс игроков и журнал ответов не изменились (сверка по контрольным суммам);
- слово, убранное из данных, стало `active = false`; после возврата в данные — тот же id, прогресс по нему на месте;
- нет `DATABASE_URL`, база недоступна или не применены миграции → код выхода 1.

## Как устроено

- **Реестр игр** — `MINI_GAMES` в `packages/shared/src/miniGames.ts`.
  - Новая игра: запись в реестре, свой модуль API и экран, строка в `gameRoutes` (`apps/web/src/screens/MiniGames/MiniGames.tsx`).
  - Хаб, карточки и хранение прогресса общие.
- **Таблицы** (миграция 0034):
  - `stress_sources`, `stress_words`;
  - `mini_game_answers` — каждый ответ, `(user_id, client_answer_id)` уникален: повтор запроса засчитывается один раз;
  - `mini_game_item_progress` — по (пользователь, игра, слово): верно / неверно / серия, обновляется в той же транзакции, что и ответ.
- **API** (`apps/api/src/modules/games`):
  - `GET /games`;
  - `GET /games/stress/round?mode=&size=` — `mistakes` / `hard` только с входом;
  - `POST /games/stress/answer` — проверка на сервере, запись только для вошедших;
  - `GET /games/stress/progress` — только с входом.
- **Защита:**
  - лимиты на аккаунт / IP;
  - cross-site POST отклоняется;
  - всё действует только на аккаунт сессии.
