# Вход через Яндекс ID

Способы входа в Зубрилку:

- **VK ID** — на сайте; в Telegram Mini App через внешний браузер.
- **Яндекс ID** — на сайте; в Telegram Mini App через внешний браузер, так же как VK.
- **Telegram** — в Mini App, автоматически.

Каждый способ — серверный, сессия одна и та же: httpOnly-cookie `session_id`. **Входа и регистрации по почте нет совсем**: ни по паролю, ни по ссылке, ни через письма. SMTP убран.

## Как работает вход

1. Кнопка «Войти через Яндекс» ведёт браузер на `GET /api/v1/auth/yandex/start`.
2. Сервер создаёт случайный `state` и пару PKCE (`code_verifier` и `code_challenge`, S256). Они сохраняются в httpOnly-cookie `ya_oauth` на 10 минут, только для пути `/api/v1/auth/yandex`. Затем сервер перенаправляет на `https://oauth.yandex.ru/authorize`, передавая `response_type=code`, `client_id`, `redirect_uri`, `state`, `code_challenge` и `code_challenge_method=S256`.
3. Яндекс возвращает браузер на `GET /api/v1/auth/yandex/callback?code=…&state=…`. Если пользователь отказался, приходит `?error=access_denied&state=…`.
4. Колбэк сначала удаляет cookie (одноразовость) и **сверяет `state`** с сохранённым. Пустой, чужой или отсутствующий `state` означает отказ: обмена кода нет, сессии нет.
5. Сервер сам, без участия браузера, меняет код на токен: `POST https://oauth.yandex.ru/token`. В запросе: `grant_type=authorization_code`, `code`, `client_id`, `client_secret`, `code_verifier`.
6. Сервер запрашивает профиль: `GET https://login.yandex.ru/info?format=json` с заголовком `Authorization: OAuth <token>`. Берутся:
   - `id` — постоянный идентификатор, ключ аккаунта;
   - `first_name` и `last_name`;
   - аватар по `default_avatar_id`.

   Почта из Яндекса не читается и не хранится.
7. Сервер выдаёт обычную сессию Зубрилки. Новый аккаунт попадает в онбординг, существующий — на главную.

Токен Яндекса живёт только в памяти на время одного запроса. Ни токен, ни код, ни секрет не сохраняются, не попадают в логи и не уходят клиенту. В лог пишутся только короткие коды ошибок (`invalid_grant`, `timeout`…).

### Какой аккаунт открывается

| Ситуация | Результат |
| --- | --- |
| Этот Яндекс-аккаунт уже связан с профилем | вход в **тот же** профиль, дубль не создаётся |
| Яндекс-аккаунт новый | создаётся новый профиль; существующие профили (в том числе с той же почтой) не затрагиваются и не объединяются |
| Пользователь нажал «Отмена» у Яндекса | `/login?yandex=cancelled` |
| Ошибка Яндекса, таймаут, неверный ответ | `/login?yandex=error` |
| Неверный или устаревший `state` | `/login?yandex=invalid_state` |
| OAuth не настроен | `/login?yandex=not_configured`; остальные способы входа работают |

Профили автоматически не объединяются никогда: почта из Яндекса для этого не используется вовсе. Поэтому на экране входа есть подсказка: если вы уже занимались через VK или Telegram, войдите тем же способом, а Яндекс ID подключите в профиле. Иначе получится новый пустой профиль. Связать Яндекс с существующим профилем можно только **изнутри этого профиля**: «Профиль → Способы входа → Яндекс ID → Подключить».

Привязка идёт через тот же поток с `?link=1`. Целевой аккаунт берётся из сессии и перепроверяется в колбэке. Яндекс-аккаунт, уже связанный с другим профилем, не переносится.

### Из Telegram Mini App

Внутри Telegram страница Яндекса (как и VK ID) не открывается, поэтому используется тот же механизм передачи входа, что и для VK (`auth_handoffs`, без новых таблиц):

1. Mini App заранее вызывает `POST /api/v1/auth/yandex/handoff`. Сервер создаёт передачу, кладёт секрет для её получения в httpOnly-cookie `ya_handoff` этого WebView и возвращает одноразовую ссылку `…/auth/yandex/start?handoff=<токен>`.
2. Нажатие «Войти через Яндекс» открывает эту ссылку во **внешнем браузере** (`Telegram.WebApp.openLink`). Mini App показывает «Ждём вход через Яндекс».
3. В браузере проходит обычный вход через Яндекс (state + PKCE). Браузер **не получает** сессию: аккаунт записывается в передачу, а браузер видит страницу «Готово, вы вошли через Яндекс — вернитесь в Telegram».
4. Mini App опрашивает `POST /api/v1/auth/yandex/handoff/claim` и сразу проверяет при возвращении в Telegram. Получить сессию может только владелец cookie `ya_handoff`, ровно один раз.

Ссылка живёт 10 минут и срабатывает один раз. Отмена у Яндекса и ошибки возвращаются в Mini App с понятным сообщением.

Передача привязана к провайдеру: в базе хранится SHA-256 от `<провайдер>:<токен>`, а не от самого токена. Поэтому токен запуска или получения, выданный для VK, на маршрутах Яндекса не находит ни одной записи («expired»), и наоборот. Отдельная колонка и миграция для этого не нужны. Передачи VK, созданные старой версией сервера (в момент обновления, не дольше 10 минут), после обновления не сработают, и пользователю нужно будет нажать кнопку ещё раз.

### Где хранится

Как и VK и Telegram: строка `auth_identities(provider='yandex', provider_user_id=<id Яндекса>)` с уникальным индексом `(provider, provider_user_id)`. Поэтому один Яндекс-аккаунт не может оказаться в двух профилях. **Миграция не нужна**: `provider` — текстовая колонка без ограничений, значение `yandex` добавлено только в TypeScript-перечисления. Существующие данные не меняются.

## Аккаунты с почтой

Входа по почте больше нет вообще: ни регистрации, ни пароля, ни ссылок. В production SMTP не был настроен, поэтому email-аккаунтов там, скорее всего, нет. Если они всё же есть:

- Их данные, пароли, прогресс и XP **не удалялись и не менялись** (таблицы `email_credentials` и `magic_link_tokens` на месте).
- Сами войти по почте они не смогут. Если у такого аккаунта подключены VK, Яндекс ID или Telegram, он входит через них.
- Если у аккаунта нет ни одного рабочего способа, но сессия ещё жива (до 30 дней), `/auth/me` возвращает `needsSignInMethod: true`. Тогда на главной и в профиле показывается предупреждение: подключите VK ID или Яндекс ID, пока вы в аккаунте. Аккаунтам с рабочим способом оно не показывается. Почта ни с чем автоматически не объединяется.
- Если сессия уже закончилась, доступ восстанавливается только вручную через поддержку: по запросу владельца к аккаунту привязывается VK или Яндекс. В коде такой операции нет.
- Строка `email` в `auth_identities` не считается рабочим способом входа. Отключить её через API нельзя (`DELETE /me/identities/email` → 404). Последний рабочий способ отключить тоже нельзя: при «почта + Яндекс» Яндекс не отключается.

Проверить, есть ли такие аккаунты в production (только чтение):

```sql
select count(*) as email_only_accounts
from auth_identities i
where i.provider = 'email'
  and not exists (
    select 1 from auth_identities o
    where o.user_id = i.user_id and o.provider <> 'email'
  );
```

## Настройка OAuth-приложения Яндекса

1. Войдите в Яндекс ID того, кто будет владельцем приложения. Откройте <https://oauth.yandex.ru> → «Создать приложение».
2. Название: «Зубрилка», иконка по желанию. Платформа: **«Веб-сервисы»**.
3. **Redirect URI** (Callback URL), точно, без лишнего слеша:
   - production: `https://zybrilka.ru/api/v1/auth/yandex/callback`
   - локально (отдельное приложение или второй URI): `http://localhost:5173/api/v1/auth/yandex/callback`
4. **Доступы** («Яндекс ID» / «API Яндекс ID»):
   - **Доступ к логину, имени и фамилии, полу** (`login:info`) — обязательно;
   - **Доступ к портрету пользователя** (`login:avatar`) — по желанию, для фото профиля;
   - доступ к почте **не нужен**: она не используется.

   Больше ничего не нужно. Сервер не передаёт `scope`: используются доступы, отмеченные в приложении.
5. Сохраните. Скопируйте **ClientID** и **Client secret**.
6. Впишите их на сервере в `infra/.env` (не в Git, не в код фронтенда):

   ```
   YANDEX_CLIENT_ID=<ClientID>
   YANDEX_CLIENT_SECRET=<Client secret>
   YANDEX_REDIRECT_URI=https://zybrilka.ru/api/v1/auth/yandex/callback
   ```

   `infra/docker-compose.yml` уже передаёт эти переменные в контейнер API. Значение `YANDEX_REDIRECT_URI` по умолчанию — production-адрес выше.
7. Перезапустите контейнер API. В логе старта строка `sign-in methods configured` покажет `yandex: true`.
8. Проверьте вручную:
   - вход новым Яндекс-аккаунтом;
   - повторный вход тем же аккаунтом — тот же профиль;
   - отмена на странице Яндекса;
   - «Подключить» в профиле аккаунта, вошедшего через VK;
   - вход через Яндекс из Telegram Mini App: браузер открывается, затем возврат в Telegram.

Ни один URL Яндекса не удалось открыть из среды разработки: DNS недоступен. Поток и параметры взяты из официальной документации Яндекс ID через её текст в поисковом индексе. Поэтому первый реальный вход (шаг 8) обязателен до того, как полагаться на кнопку.

## Переменные окружения

| Переменная | Где | Обязательна |
| --- | --- | --- |
| `YANDEX_CLIENT_ID` | API | для входа через Яндекс |
| `YANDEX_CLIENT_SECRET` | API, только сервер | для входа через Яндекс |
| `YANDEX_REDIRECT_URI` | API | для входа через Яндекс; совпадает с Redirect URI приложения |
| `YANDEX_REQUEST_TIMEOUT_MS` | API | нет (5000) |

`SMTP_*` больше не читаются. Если они остались в `infra/.env`, они просто игнорируются.

## Ограничения

- **Аватар.** Фото Яндекса показывается по ссылке `avatars.yandex.net`, локальная копия не делается (для VK и Telegram она делается).
